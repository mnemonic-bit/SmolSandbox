# Feature 0022: Install all Matt Pocock skills in the Codex template

## Status

In progress. The template, regression coverage, operating guidance, and
application version `0.16.0` are implemented. All seven independent Rust
checks, deterministic provisioning fixtures, and a real upstream installation
in a disposable container passed. AC-06 remains `not_run`: Linux x64 and ARM64
SmolVM guests, Codex skill discovery, and retained-home guest restarts require
a compatible native host. See [Feature 0022 validation](feature-0022-validation.md).
The feature is not marked `Implemented` until every mandatory criterion passes.

## Outcome and baseline

New Codex definitions generated by `smolsbx create-config --harness codex`
install every installable skill from `mattpocock/skills` for Codex. Each skill
and its supporting files remain available after the persistent Codex home
is mounted and seeded. The implementer owns the template change, regression
coverage, operating guidance, application version bump, and validation record.

Specification preparation observed commit
`3e5870d04e47327f9f29f48215f2552b8fe096b0`, application version `0.15.0`,
and a clean working tree on 2026-11-22. The Codex template currently runs:

```sh
npx -y skills@1.8.1 add mattpocock/skills --skill=grill-me --skill=grilling --agent codex --global --yes
mkdir -p /root/.codex/skills && cp -aL /root/.agents/skills/grill-me /root/.agents/skills/grilling /root/.codex/skills/
```

`Profile::template` in `src/config.rs` embeds `templates/codex.smlbx`.
The final template initialization command snapshots `/root/.codex` into
`/opt/codex-home`. `Lifecycle::seed` in `src/lifecycle.rs` copies missing
files from that snapshot into the mounted persistent home. Selecting all
skills without replacing the two-directory copy would leave additional
skills outside the snapshot.

This feature supersedes the two-skill selection required by
[Feature 0016](feature-0016-update-codex-and-selected-tool-versions.md)
and preserved by [Feature 0018](feature-0018-update-codex-to-0.171.0.md).
Preserve their historical observations and validation records.

## Skill selection and installation

Use the following noninteractive Codex-global installation command:

```sh
npx -y skills@1.8.1 add mattpocock/skills --skill '*' --agent codex --global --yes
```

1. Replace the explicit `grill-me` and `grilling` selectors with the quoted
   wildcard selector. Preserve shell quoting when encoding the command in
   the TOML template so the shell passes a literal `*` to the installer.
2. Retain the `codex` agent selection, global installation, and confirmation
   suppression. Do not use `--all`: the installer documents that option as
   selecting all agents as well as all skills.
3. Define the expected skill set as every installable skill discovered by
   skills CLI `1.8.1` in the upstream repository revision fetched during
   provisioning. Keep the skill names and count dynamic; new upstream
   skills require no local enumeration change. Retain `grill-me` and
   `grilling` whenever those skills remain in the upstream set.
4. Retain the installer pin `1.8.1`. Retain the existing unpinned upstream
   repository source. Installer upgrades and upstream revision pinning are
   separate changes. Record the resolved upstream revision and discovered
   skill inventory during validation so the observed result is reproducible.
5. Preserve the provisioning failure behavior: an installation or skill-copy
   failure returns a nonzero result. Do not report a successful installation
   when the discovered skill set is empty or required skill files are absent.

The [skills CLI 1.8.1 command reference](https://github.com/vercel-labs/skills/blob/v1.8.1/docs/commands.md#skills-add)
documents the quoted wildcard selector, agent selection, global scope, and
noninteractive options. The reference was inspected on 2026-11-22. Upstream
skill content is maintained in [mattpocock/skills](https://github.com/mattpocock/skills).
The wildcard command has not been executed during specification preparation.

## Prepared home and retained state

1. Replace the two-directory copy with a copy of every installed Matt Pocock
   skill into `/root/.codex/skills`. Preserve each skill's complete relative
   file tree, supporting resources, and executable permissions. Do not copy
   only `SKILL.md`, flatten directories, or select a fixed list of names.
2. Materialize the copied skills as files and directories that do not depend
   on `/root/.agents/skills` or an installer checkout at runtime. Dereference
   installation symlinks, as the existing `cp -aL` command does. Verify that
   removing access to the installation source leaves the copies readable.
3. Complete skill copying before the existing `/opt/codex-home` snapshot.
   Limit the copied set to skills installed from `mattpocock/skills`; preserve
   unrelated skills and Codex home files.
4. Retain missing-files-only persistent-home seeding. An empty home receives
   the complete prepared skill set. A retained home receives missing skill
   files while keeping existing files byte-for-byte, including user-edited
   skills, credentials, settings, sessions, and unrelated custom skills.
5. Preserve the existing warning-and-continue behavior when runtime home
   seeding fails. This feature does not add deletion, forced skill updates,
   automatic refresh on start, or synchronization with upstream removals.

The upstream set is resolved when provisioning actually runs. Reusing an
existing base does not fetch new skills. Existing persistent skill files
may differ from the prepared defaults because seeding preserves user files.

to describe the complete upstream skill set and complete home snapshot.
Update the assertions and ordering checks in
`codex_template_preserves_provisioning_tools_pins_and_verification` in

Review `four_templates_are_complete_and_isolated`,
`codex_template_default_hosts_are_exposed_by_definition`, and
`codex_template_seed_settings_are_parsed_and_explicit`. Preserve the other
three templates, network allowlists, Codex version and settings, MCP
installation and registration, other tool versions, and lifecycle policy.
Retain the existing `seed_commands_are_non_clobbering_and_failures_only_warn`
regression in `tests/application.rs`.

Update [RUST-APPLICATION.md](../RUST-APPLICATION.md#template-adoption) to
describe the expanded skill set and explicit adoption. Existing user-owned
definitions remain unchanged. Users generate a separate definition:

```text
smolsbx create-config --harness codex --smolfile ./codex-all-skills.smlbx
```

Users compare the generated definition with their selected definition before
selecting or editing the desired file. Changed definition bytes select a new
base generation under the existing identity rules. Preserve `REVISION` in
`src/lifecycle.rs`; the template change does not alter Rust machine-creation
policy for unchanged definition bytes.

When implementing the feature, increment the minor version in `Cargo.toml`
and the matching `smolsandbox` entry in `Cargo.lock`. From the observed
`0.15.0` baseline, the feature version is `0.16.0`. If the implementation
baseline changes, derive the minor bump from that baseline.
