## Outcome and baseline

New Codex definitions generated by `smolsbx create-config --harness codex`
install exactly `@openai/codex@0.171.0`. The implementer owns the template
update, matching regression expectation, application version bump, active
documentation, and validation evidence.

Specification preparation observed commit
`7151713dcf703e02bcca772994243bf2b8e0ae92`, application version `0.11.2`, and
`npm install -g @openai/codex@0.169.0` in `templates/codex.smlbx` on
2026-11-22. The request names `0.164.0` as the starting version;
[Feature 0016](feature-0016-update-codex-and-selected-tool-versions.md)
records that historical baseline and the intervening `0.169.0` target.
Feature 0018 updates the current pin to `0.171.0` without reverting the
other Feature 0016 updates.

`Profile::template` in `src/config.rs` embeds `templates/codex.smlbx`.
The independent regression
`codex_template_preserves_provisioning_tools_pins_and_verification` in the
same source file asserts the exact Codex installation command.

## Scope and compatibility

Limit provisioning changes to the Codex package pin. Retain other tool
versions, the other three templates, model and seed settings, skill
selection, network allowlists, MCP installation and verification, and the
prepared Codex home snapshot. Codex installation continues to precede MCP
installation. Preserve the existing workspace launch with `codex --no-daemon`
and device authentication with `codex login --device-auth`.

Preserve existing user-owned definitions and persistent Codex state.
Updating the executable does not rewrite an existing definition. Users
adopt the new template explicitly by generating a separate definition:

```text
smolsbx create-config --harness codex --smolfile ./codex-0.171.0.smlbx
```

Users compare the generated definition with their selected definition
before selecting or editing the desired file. Unchanged definitions retain
their pins. Changed definition bytes select a new base generation under the
existing lifecycle rules. Preserve `REVISION` in `src/lifecycle.rs`; the
template update does not change Rust machine-creation policy for unchanged
definition bytes.

Retain missing-files-only home seeding. Do not reset credentials, settings,
skills, or sessions to make validation pass. Record any observed upstream
state migration; do not claim compatibility with older Codex versions
without evidence. If validation requires changes beyond this scope, record
the failure and revise the specification before expanding the implementation.
