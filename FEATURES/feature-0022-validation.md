The fixture captures installer arguments and verifies the literal `*`,
Codex-only agent, global scope, and confirmation suppression. The fixture
includes `grill-me`, `grilling`, and a third skill with nested resources,
an executable, and installation/resource symlinks. An uppercase lock name
exercises the pinned installer's name normalization. Whole-tree comparisons
cover relative paths, bytes, modes, and removal of source dependencies.
Unrelated source skills are excluded; existing custom skills and settings
are preserved in the prepared home.

Empty, missing, malformed, and stale inventories fail. A no-op installer
after source metadata reset cannot reuse stale source entries. Missing
`SKILL.md` and a failing copy command fail. A nonzero installer fails; an
installer that exits zero but prints a partial-installation, category-conflict,
or lock-write diagnostic also fails, including ANSI-colored output.
The copy-failure fixture returns 31; the other recorded failure cases
return 1. Failure is the expected outcome for these injected cases.

The script extracts the actual `Lifecycle::seed` shell command from
`src/lifecycle.rs` and executes it with temporary path substitutions. An
empty home receives the complete prepared tree. A retained home gains
missing resources and a missing whole skill while preserving edited skill
bytes, settings, credentials, sessions, and a custom skill. Repeated seeding
preserves the resulting inventory. The Rust application seed regression
separately verifies warning-and-continue behavior on seeding failure.
